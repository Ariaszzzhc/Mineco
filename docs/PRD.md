# Mineco 产品需求文档（PRD）

> 版本:v1 · 技术无关描述 · 只讲「是什么产品、要做什么功能」

## 1. 产品概述

**Mineco 是一款 macOS 原生的 AI 编程助手桌面应用。** 用户在应用里与一个 AI agent 对话,agent 能够理解代码库、读写文件、执行命令、完成复杂的编程任务。应用支持同时开启多个独立会话并行工作,并提供模型连接、权限审批、使用量统计等配套能力。

一句话:**一个跑在你 Mac 上的、可同时处理多任务、可管账号和成本、可审批危险操作的 AI 编程助手。**

## 2. 背景与动机

开发者日常有大量「读代码、改代码、跑命令、查日志」的机械工作。通用聊天工具不直接操作本地文件系统,而终端类 agent 又缺一个顺手的图形界面。Mineco 想要的是:

- **原生体验**:Mac 上的原生窗口,不是浏览器套壳;流式输出、快捷键、系统级集成。
- **多任务并行**:一边让 agent 改一个模块,一边开另一个会话查问题,互不干扰。
- **可控可审计**:危险操作(执行命令、改文件)要能逐个审批;花了多少钱、用了多少 token 要看得见。
- **账号与端点可切换**:支持多套 API 账号 / 自定义服务端点,在一个会话进行中也能切换。

## 3. 目标用户

- 日常在 macOS 上写代码的个人开发者 / 小团队工程师。
- 习惯用 AI 辅助编程、希望在本地代码库中让 AI 直接动手的用户。
- 关注 API 成本和操作安全的用户。

## 4. 核心使用场景

1. **改一个功能**:打开项目 → 新建会话 → 用自然语言描述要改什么 → agent 读相关文件、改代码、跑测试 → 用户审阅每一步。
2. **并行排查**:开两个会话分别调查不同问题,其中一个在跑长任务时,另一个照常输入和响应。
3. **切账号继续**:某个会话进行中发现要换一套 API 凭证 / 换模型,切换后对话内容连续不丢失。
4. **复盘成本**:事后查看按模型 / 按会话 / 按天的 token 用量与花费。

## 5. 功能需求

### 5.1 会话（Session）
- 创建会话(指定一个本地项目目录作为工作区)。
- 多轮对话:用户发消息,agent 流式返回(文字逐字出现、工具调用过程可见)。
- 中断正在进行的回合。
- 关闭会话。
- 一个会话绑定一个工作区目录;agent 的文件操作限制在该目录(及明确允许的额外目录)内。

### 5.2 Agent 能力
- 理解自然语言指令并拆解为多步任务。
- 读取 / 编辑 / 创建文件,搜索代码,执行 shell 命令。
- 多轮自主执行(读取 → 思考 → 操作 → 验证),直到任务完成或被打断。
- (复用成熟 agent 引擎的全部内置能力,产品层不自己实现 agent 逻辑。)

### 5.3 多会话并发
- 同时开启多个会话,**互相独立、互不阻塞**。
- 一个会话在执行长任务时,其他会话的输入和输出不受影响。

### 5.4 连接配置（Profile）
- 维护多套「连接配置」(Profile):每套包含服务来源、访问凭证、默认模型、权限策略等。
- 在设置界面增删改查 Profile。
- 指定一个默认 Profile。
- 新建会话时选用某个 Profile(缺省用默认)。
- **对进行中的会话切换 Profile**:切连接 / 切模型 / 切账号。
  - 若该会话当前空闲:立即切换,对话连续不丢失。
  - 若该会话正在执行任务:不打断当前任务,等当前回合结束后自动应用切换。
- 一期支持的 Profile 类型:**API Key 直连** 与 **自定义服务端点**(指向兼容接口的网关)。订阅登录类鉴权一期不做。

### 5.5 权限审批
- agent 执行「可能改变环境」的操作前(执行命令、写文件等),向用户请求确认。
- 应用弹出审批界面,展示:要执行什么、影响范围、建议的处置。
- 用户选择:允许 / 拒绝;可选择「本次允许 / 记住规则以后不再问」。
- 审批期间会话暂停等待,用户决定后 agent 继续。
- 权限模式可整体切换(例如「只读探索」模式、「自动接受编辑」模式),便于不同场景。

### 5.6 使用量统计
- 记录每次 agent 回合的模型用量:输入 / 输出 / 缓存 token 数、估算花费、所用模型。
- 按维度聚合查看:按模型、按会话、按时间区间。
- 在应用内以用量视图呈现,帮助用户掌控成本。

### 5.7 会话历史与恢复
- 所有会话的对话内容持久保存。
- 重新打开应用后,能看到历史会话列表并**恢复(Resume)**任意一个继续对话,上下文连续。
- 即使应用或后台异常退出,数据也不丢失,重启后可恢复。

### 5.8 项目（Workspace）管理
- 记录「最近打开的项目」列表。
- 按项目归类查看其下的会话。
- (结构性能力,支撑会话的组织与切换。)

## 6. 用户体验要求

- **原生 macOS 视觉与交互**:符合系统设计语言,键盘可达,流式输出流畅。
- **低延迟**:用户发话后首字尽快出现;切换会话 / 切 Profile 不卡顿。
- **过程可见**:agent 的思考、工具调用、结果实时可见,而非黑盒等待。
- **安全可控**:危险操作必须显式审批,绝不静默执行。

## 7. 非功能性要求

- **响应性**:多会话并发时,UI 不应因某个会话的重负载而冻结或明显掉帧。
- **隔离性**:不同会话之间互不影响——一个会话的崩溃 / 卡顿不波及其他会话和应用。
- **可靠性**:本地数据(会话、配置、用量)持久且一致,异常退出可恢复。
- **隐私**:用户数据与凭证保存在本机用户目录下,不上传第三方(除用户主动配置的服务端点)。

## 8. 范围与边界（v1 不做什么）

明确**不在 v1 范围**内的:

- ❌ Web 客户端 / 浏览器访问(v1 只做 macOS 原生)。
- ❌ 订阅账号登录(OAuth 类鉴权);v1 只支持 API Key 与自定义端点。
- ❌ 远程 / 多客户端连接(后台与界面同机同包,不作为网络服务)。
- ❌ 多人协作 / 团队共享会话。
- ❌ 旧版本中的 git worktree 工作区、会话笔记、自研 skills 体系、子 agent 自定义编排、自研上下文压缩等能力(v1 依赖成熟 agent 引擎的内置能力,不自建)。

## 9. 验收标准（v1）

- ✅ 能创建会话、多轮对话,看到流式输出与工具调用过程。
- ✅ 能同时开 2 个以上会话并行工作,互不阻塞。
- ✅ 能配置多套 Profile 并切换;进行中会话切 Profile,空闲立即生效、运行中跑完回合后生效,且对话不丢。
- ✅ 危险操作弹出审批,允许 / 拒绝 / 记住规则均生效。
- ✅ 用量统计按模型 / 会话 / 时间可查,数字与实际调用一致。
- ✅ 关闭应用重开,历史会话可列出并 Resume,上下文连续。
- ✅ 强杀后台进程后重启,数据无丢失。
